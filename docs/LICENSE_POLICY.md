# Licence policy

ClearTrace is Copyright (c) 2026 Arpan Bom, all rights reserved, under the evaluation-only
permission in [`LICENSE`](../LICENSE) (SPDX `LicenseRef-ClearTrace-Evaluation-Only`). Every
ClearTrace manifest carries that identifier: each `pyproject.toml` has
`license = { text = "LicenseRef-ClearTrace-Evaluation-Only" }`, `web/package.json` has
`"license": "UNLICENSED"` and `"private": true`, and the Helm chart and the SBOM's ClearTrace
component carry the same identifier.

Third-party components, data and files keep their own licences. They are listed in
[`THIRD_PARTY_LICENSES.md`](../THIRD_PARTY_LICENSES.md), generated by
`tools/third_party_licences.py` from `uv.lock`, the installed package metadata and
`web/package-lock.json`.

## Rules for our own dependencies

"Our own dependencies" are the non-dev Python packages that `uv export --no-dev --all-packages`
resolves from `uv.lock`, and the non-dev npm packages of the web build in `web/package-lock.json`.

| Class | Licences (SPDX) | Rule |
| --- | --- | --- |
| Permissive | MIT, MIT-0, MIT-CMU, BSD-2-Clause, BSD-3-Clause, 0BSD, Apache-2.0, ISC, PSF-2.0, Python-2.0, CNRI-Python, Unlicense, Zlib, CC0-1.0, TCL, PostgreSQL, CC-BY-4.0 (data, with attribution) | Allowed. |
| Weak copyleft | LGPL-\*, MPL-\* | Allowed only when used unmodified and listed, with its source location, in the "LGPL and MPL components (used unmodified)" table of `THIRD_PARTY_LICENSES.md`. For LGPL libraries the user keeps the right to replace them; LICENSE does not restrict it. |
| Strong copyleft | GPL-\*, AGPL-\* | Not allowed. |
| Source-available | SSPL, BUSL / BSL-1.1, Elastic License | Not allowed. |
| Unknown | No licence found in the metadata or licence files | Not allowed until the licence is identified. |

An SPDX expression is judged as a whole: `A OR B` takes the more permissive choice, `A AND B`
the stricter term. So `MPL-2.0 AND (Apache-2.0 OR MIT)` (orjson) is weak copyleft.

Packages whose platform marker excludes them from the Linux build (for example `pywin32`,
Windows only) are listed as not installed and are not shipped in the images.

## Container base images

Operating-system packages inside the deployed images come from third-party base images
(PostgreSQL, NATS, Keycloak and others) and from the Debian slim base of the ClearTrace
`core-api` image. CI builds the `core-api` image, builds a Syft SBOM per image and a
licence report (`scripts/ci_image_sbom.sh`, `tools/image_licence_report.py`, artifact
`image-sbom`). GPL/LGPL OS packages in those bases are unmodified distribution packages;
they are listed in the approved exception
[`docs/licence_exceptions/SHIPPED_IMAGE_OS_PACKAGES.md`](licence_exceptions/SHIPPED_IMAGE_OS_PACKAGES.md).
Application-layer packages inside `core-api` remain under the rules above.

## Enforcement

`tools/licence_gate.py` runs in CI on every build and fails when:

- a ClearTrace manifest does not carry the ClearTrace licence identifier;
- any of our own dependencies is strong copyleft, source-available or unknown;
- an LGPL or MPL dependency is not in the "used unmodified" table;
- `THIRD_PARTY_LICENSES.md` is out of date with the lock files;
- a shipped (scope `required`) component in `sbom.json` records a strong-copyleft or
  source-available licence;
- a strong-copyleft or source-available licence token appears in our own source paths.

There is no allow-list of individual findings and no ignore file; the rules above are the policy.

## Relation to the blueprint

The blueprint is stricter than this policy. Line 573: "shipped components must be permissive
(MIT, BSD, Apache-2.0, PostgreSQL, ISC)". Line 716: "licence gate (fails on AGPL, GPL, LGPL,
SSPL, BSL, Elastic, MPL inside shipped images unless an approved exception file lists them)".
`THIRD_PARTY_LICENSES.md` lists the LGPL and MPL libraries used unmodified, but the
GPL-family OS packages in base images are covered by the approved exception file above.
Application dependencies stay gated. T-28 records the image inventory and the exception.
